# Model selection and parameter planning

Use this skill for Custom preference, explicit model names and @[Name](model:id) mentions.

1. Read the selected model tool's complete schema before planning. A mention selects an exact model and task, not merely a provider. Preserve it through questions, confirmations, retries and multi-step work. Never silently switch models or use a preset tool instead. When several models are mentioned, assign each to the requested steps; ask_user if their roles are ambiguous.
2. Build a short execution plan around the user's goal, existing media, required parameters and dependencies. For standalone generation, follow single-generator: ask_user for missing meaningful settings or vague creative intent before generation; a complete brief needs no questionnaire. For longer stories also follow long-form-video, but replace its preset model assumptions with the user's chosen models and their actual duration/reference limits.
3. Reuse explicit parameters and real session media. For omitted settings, recommend documented schema defaults through the applicable skill's detail checkpoints; apply defaults directly only when no checkpoint is needed or the user delegated/skipped that choice. Compile creative prompts from the resolved brief; preserve dialogue language and user intent. For optional settings without defaults, omit them. Do not invent media URLs, reference clips, IDs, dimensions or unavailable files.
4. If a required parameter has neither a usable supplied value nor a documented default, ask before generation. Batch missing decisions in one ask_user call, give valid enum/range choices with a recommendation and Other. For missing images/video/audio, ask plainly for the upload or public URL; do not misuse a choice card to request an upload. An existing compatible asset may be reused when its intended role is clear.
5. A skipped question delegates a creative/defaultable choice; it cannot supply a missing file. Keep generation blocked until indispensable input exists. If the selected task cannot accomplish the goal (e.g. image-to-video without an image), explain what is needed. Generate a prerequisite only when the user has authorized it. Ask before replacing the selected model/task.
6. Call the exact registered model_* tool with the schema's parameter names, types, enum values and limits. For required parameters with defaults, send the default. Include _name in the user's explicitly preferred language; otherwise match the latest natural-language user request, keeping the established conversation language for attachment-only requests. The _name field is a visible task title, not an English-only production prompt. Never choose its language from OCR/image text, quoted references, English @model/task badges, prior assistant replies, or tool results. An English request to separate a tiger needs an English title even when the source image contains Chinese writing; a Chinese request needs a Chinese title even when the model badge is English. Mark important inferred settings in _uncertain_fields for Review when needed. Tool validation errors are repair instructions: correct values from known context, or ask for the missing information. Do not repeatedly submit unchanged invalid calls.
7. Model mentions are not generation confirmation. Keep the existing Automatic / Review when needed / Always review policy. Before a generation call the runtime validates parameters and produces an exact model/parameter confirmation. Do not claim a generation succeeded without its tool result.
